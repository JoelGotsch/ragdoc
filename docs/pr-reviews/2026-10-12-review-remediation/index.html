What / why

What. split/8-review-fixes is the accumulated result of a review-remediation sweep of the ragdoc library, landed as eleven numbered phases (Phase 0 bug fixes through Phase 10 docs) followed by a second round of targeted review fixes. It is pre-1.0 and deliberately breaking: every old spelling is removed rather than shimmed, and the breaking list lives in CHANGELOG.md.

Why. The review found the sync layer duplicated across pipelines with inconsistent change detection, a pipeline class whose stage placement was only validated by prose errors, an element model that silently built empty elements on misspelled keywords, no shared LLM retry and timeout policy (SDK retries stacked under library retries), unbounded fan-out that leaked un-awaited coroutines, and a knowledge-graph extractor with no documentation. The branch addresses each with a structural fix plus pinned tests rather than point patches.

Design

The branch has six independent design threads. The first two reshape the sync layer and are the centre of gravity; the rest are structural fixes to a single subsystem each.

  1. One sync engine, three thin pipelines. On main each of VectorStorePipeline and DocumentStorePipeline carried its own copy of plan/apply/run with hand-rolled change detection and except BaseException error collection (old plan, old apply). Head introduces SyncEngine[T]: a generic streaming core that owns token comparison, per-source concurrency with back-pressure, error isolation, orphan deletion and the write discipline. A pipeline now contributes only a resolver (request → SyncPlanInput) and a producer coroutine. MentionStorePipeline (extraction) composes the same engine.
  2. Interruption-safe store writes. A new optional SourceReplaceStore protocol lets the engine update a source new-before-old; the shared Qdrant base implements blank-then-stamp two-phase writes so a crash mid-write can never read as “unchanged”.
  3. Pipeline split at the sync boundaries. DocumentPipeline becomes a composition of IngestPipeline (parse → process → stamp source_id) and ChunkPipeline (split → chunk → mint ids). A stage on the wrong side is now a TypeError at construction because no parameter exists for it, replacing runtime prose rejections.
  4. One LLM reliability layer (ragdoc.llm): narrow structural client protocols, one retry policy, SDK retries disabled underneath, and two failure classifiers that drive per-site degrade semantics.
  5. Strict element model: extra="forbid", value-keyed soup cache, field-based equality, structural splitting of oversized tables and lists into same-type fragments.
  6. Bounded fan-out everywhere via a single factory-based helper run_ordered, replacing coroutine-list gathers that leaked un-awaited coroutines on failure.

Key contracts. A pipeline plugs into the engine through two small types. SourceReplaceStore is detected structurally (isinstance on a runtime_checkable Protocol) so any custom store with a replace_source method is opted in automatically. The Producer type documents the one subtle choice each pipeline makes: whether a filtered document is None (preserve stored state) or an empty change (delete stored items).

What the write discipline does and does not guarantee

  • Guaranteed: a source whose write was interrupted never reads as unchanged. Qdrant multi-batch writes land with blank hashes and are stamped last (_batched_upsert); list_source_state reports a source whose points disagree as blank (_list_source_state); LocalDocumentStore writes via temp file, fsync and os.replace (write_text_atomic).
  • Guaranteed: with a SourceReplaceStore, a failure while writing new items keeps the old items. Non-replace stores still do delete-then-upsert; a failed upsert leaves the source empty and it is re-processed as new (_write_source).
  • Not guaranteed: a failure at the stale-delete or stamp step of a replace leaves old and new points side by side (or new points unstamped). A single-request write has no rollback. A pre-existing point already overwritten is not restored (_rollback_created). Nothing is a transaction across the corpus.
  • Not guaranteed: a source yielding zero items stores no token and is re-produced every run; plan() only logs sources that fail during production (they are absent from the ChangeSet).

Implementation

Read the sync path first: it is where the most code moved and where the behavioural guarantees changed. The stack below follows VectorStorePipeline.run() for one updated file in direct mode over Qdrant. On main the call was literally apply(plan(...)): plan chunked the whole corpus with asyncio.gather, apply embedded everything, then ran all stale deletes followed by all upserts. On head, resolution and production are generic engine code, each source is embedded and written as it streams through, and the Qdrant write is new-before-old with a stamped commit marker.

1 · Pipeline split by boundary (Phase 9)

DocumentPipeline on main did everything in one class and exposed parse_and_process / chunk_document as the two sync entry points, with chunk_document re-running the processor chain on an already-processed document. Head replaces that with IngestPipeline and ChunkPipeline; DocumentPipeline.run is now four lines composing them. The sync pipelines take the boundary-appropriate type: DocumentStorePipeline(ingest=…) and VectorStorePipeline.from_document_store(chunk=…). Two correctness fixes ride along: source_hash is no longer faked from content_hash (compare old with resolve_chunk_provenance), and chunk ids are minted pipeline-side as deterministic UUIDs so the default pipeline can upsert into Qdrant without a custom chunk_id_fn.

2 · LLM reliability layer (Phase 7 + review fixes)

ragdoc/llm.py is new. It defines narrow structural protocols (ChatClient, EmbeddingsClient) so call sites demand only the capability they use, and one retry loop that every LLM call shares. Two review-fix details matter in practice: without_sdk_retries wraps a real AsyncOpenAI in with_options(max_retries=0) so the SDK's own retries no longer stack under the library's (previously up to (max_retries+1)×3 HTTP attempts), and a Retry-After header is honoured but capped at backoff_max. _classify decides retryability: 429, connection/timeout and 5xx retry; other 4xx, refusals, validation errors and non-openai errors raise immediately. Two classifiers drive per-site degrade behaviour: is_llm_failure (image summary skips one image with a warning, see _process_one) and is_size_related_failure (KG halving, below). OpenAIEmbedder batches at 256 inputs per request under the same policy and raises on a vector-count mismatch. openai is imported lazily so the base install stays lean.

3 · Strict element model (Phase 6 + review fixes)

BaseElement now carries validate_assignment=True, extra="forbid", with a before-validator that turns the pre-refactor html_content= / innerhtml= keywords into an error naming html (reject_renamed_element_keywords). Between the Phase 6 refactor and this fix, those keywords silently built an empty element, which is why the CHANGELOG calls the JSON break out explicitly. Three smaller fixes: the soup cache is keyed on the html string's value, not identity (_parsed), which makes it effective for Footnote (fresh string per access) while Image bypasses it; equality is field-based so reading .text no longer makes two identical elements unequal; and the RawText validator guarantees only the outer <div> without unwrapping or re-serialising content (MinerU code blocks therefore ship pre-escaped <pre><code> via build_code_html). Document.content_hash is the canonical-JSON hash over (title, elements) with inline ref ids normalised to ordinals, so a re-parse of an unchanged file hashes identically.

4 · Structural splitting of oversized elements

split_oversized_element keeps its three tiers, but tier 1 is rebuilt around plan_html_split: a table is cut on rows with caption/colgroup/thead repeated in every fragment, a list on items with <ol start=…> continued, and the plan returns None when bare text sits directly under the outer tag (cutting there would drop it). build_fragment_element keeps the fragment's type (Table stays Table, DocumentList stays DocumentList); only generic containers fall to RawText. Tiers 2 and 3 now verify the rendered result against max_tokens rather than trusting the budget arithmetic. Consumers that looked for RawText fragments in splits break; chunk counts for such sources change once.

5 · One fan-out helper, and the extraction stage

run_ordered replaces fan_out and the ad-hoc asyncio.gather lists in DocumentSummarizerProcessor (call), ImageSummaryProcessor (call), LLMHeadingResolver, FootnoteProcessor and MentionStorePipeline (call). It takes zero-argument factories so a coroutine is created only when it is about to run, and on failure cancels and awaits siblings. The final commit on the branch makes resolve_semaphore reject concurrency < 1 instead of hanging forever on Semaphore(0).

Extraction (src/ragdoc/extraction/, 3825 new lines) lands as a typed first-class stage rather than a processor: an Extractor[PayloadT] returns Mentions and never touches document.metadata. MentionStorePipeline is the third SyncEngine client. The review fixes there: _extract_with_halving halves only on is_size_related_failure (a 401 or 429 used to trigger recursive halving, multiplying the failing calls), an edge referencing an unknown node is dropped with a warning via drop_dangling_edges instead of failing the source, gleaning is a proper conversation continuation, and per-source split extraction is bounded by split_concurrency (default 4) instead of unbounded.

6 · Tests, notebooks and docs

Tests account for roughly half the diff (164 files). New suites worth opening when reviewing a thread: tests/stores/test_qdrant_write_safety.py (blank-then-stamp, rollback, mixed-state detection), tests/test_llm.py (retry policy, Retry-After cap, SDK-retry bypass, classifiers), tests/test_element_strict_keywords.py and tests/test_element_model.py, tests/splitting/test_structural_split.py, tests/utils/test_concurrency.py, tests/test_content_hash.py and tests/test_public_api.py (pins the root export surface).

Notebooks under docs/notebooks/ are now executed in CI on four layers (marimo check, pytest docs/notebooks/ collecting test_* cells, tests/test_notebooks.py wrapping each with app.run(), and the offline-by-default rule). Three notebooks are new (document_model.py, extraction.py, pipeline_walkthrough.py); the sync notebooks now run for real against in-memory stores. docs/guide/sync-engine.md, docs/guide/extraction.md, docs/guide/processing.md and docs/api/llm.md are new pages; CLAUDE.md was reconciled with the code twice and the last docs commits are explicitly “correct statements found false by an audit”. Tooling: ruff and basedpyright are pinned to exact versions, CRLF endings normalised, executable bits dropped, and plans/ / designs/ are gitignored working notes.
